## 상세

### 1. [높음] 알레르기·식단 재검사가 한 글자 용어와 '닭' 계열 재료를 놓침

- **위치:** `src/recipe.py:310-312`(`_hits`), `src/recipe.py:66-79`(`ALLERGEN_TERMS`·`MEAT_TERMS`)
- **문제:** 한 글자 용어(게·굴·빵·콩·잣·닭)는 재료 이름과 글자가 완전히 같을 때만 걸린다. 그래서 이 글자가 들어간 흔한 재료가 필터를 그대로 통과한다.
- **발생 상황:** 가짜 레시피로 `reject_reason()`을 직접 돌렸을 때 아래가 모두 통과(`None`)했다.
  - 갑각류: 대게, 게살
  - 조개류: 굴소스. `SEASONINGS`에도 있어 추가 재료 "소량" 조건에서도 통과한다.
  - 밀: 식빵
  - 대두: 콩가루
  - 견과류: 잣가루
  - 채식·비건·페스코: 닭가슴살, 닭다리, 닭날개
- 모델이 조건을 어기면 알레르기가 있는 사용자나 채식 사용자에게 걸러야 할 레시피가 보인다. 사용자가 "게"를 직접 입력해도 게살·대게는 걸리지 않는다.
- **확실성:** 확인함(직접 실행)

### 4. [중간] 연결 오류가 아닌 psycopg2 예외가 화면까지 올라감

- **위치:** `src/db.py:115`, `src/db.py:139-143`. 호출하는 쪽은 `src/account_ui.py:107`, `:302`, `:344`, `:355`, `:375`, `:416`이다.
- **문제:** `pool.getconn()`이 내는 `psycopg2.pool.PoolError("connection pool exhausted")`는 `OperationalError`·`InterfaceError`가 아니라서 `StorageError`로 바뀌지 않는다. 호출하는 쪽은 `db.StorageError`만 잡는다. `.streamlit/config.toml`에 `showErrorDetails` 설정이 없고, 설치된 Streamlit 1.66.1의 기본값은 `full`이다.
- **발생 상황:** DB 작업이 동시에 5개(풀 최대)를 넘으면 이 예외가 난다. 앱 맨 위의 `current_user`(쿠키 조회)에서 나면 페이지 전체가 스택 트레이스와 서버 경로를 보이며 멈춘다. 메모 저장·삭제·프로필 저장 콜백에서도 같다. PRD 7("스택 정보를 노출하지 않는다")에 어긋난다. 접속 문자열은 오류 문구에 들어가지 않는다.
- **확실성:** 가능성 있음(예외 전달 경로는 확인함, 동시 접속은 재현하지 않음)

### 6. [중간] 동시 시도로 로그인 실패 제한을 넘을 수 있음

- **위치:** `src/auth.py:123-136`(`limiter.check` → argon2 확인 → `limiter.fail`)
- **문제:** 확인과 실패 기록이 한 번에 묶여 있지 않아, argon2 확인이 도는 동안 다른 세션의 시도도 `check()`를 통과한다. `_failures` 딕셔너리는 임의 이메일마다 커지고 지워지지 않는다.
- **발생 상황:** 여러 Streamlit 세션에서 같은 이메일로 동시에 로그인하면, 실패가 기록되기 전에 5번을 넘는 시도가 비밀번호 확인까지 간다.

### 7. [중간] 구글 로그인을 거치면 저장이 이어지지 않을 수 있음

- **위치:** `src/account_ui.py:285-287`(`request_login_to_save`), `:68-70`(`start_google_login`), `:290-294`
- **문제:** 저장하려던 레시피(`pending_save`)와 결과(`recipe_result`)가 세션 상태에만 있다. `st.login()`은 구글로 갔다가 돌아오는 방식이라 새 세션이 된다.
- **발생 상황:** 로그인하지 않은 사용자가 저장을 누르고 구글 로그인을 고르면, 돌아왔을 때 저장도 되지 않고 레시피·재료도 사라질 가능성이 크다. PRD 5.2에 어긋난다. 비밀번호 로그인은 같은 세션이라 문제없다.
- **확실성:** 가능성 있음(`st.login`의 페이지 이동 동작에 달려 있음, 실행 확인 안 함)

- **확실성:** 가능성 있음(높음, CLAUDE.md에 적힌 Streamlit 동작에 근거, 실행 확인 안 함)

- **실패 표시:**
  - 새로 시도할 때 이전 결과를 먼저 지운다.
  - `recognize_error`·`recipe_error`는 다음 시도까지 남는다.
  - 예상하지 못한 예외는 종류만 화면에 보이고 내용은 `fridge_app` 로거에만 남는다.
  - `st.rerun()`은 `try` 밖에 있다.
- **계정 보안:**
  - 레시피 SQL은 모두 매개변수 바인딩이고 `user_id`로 제한한다.
  - 비밀번호 계정과 구글 계정을 합치지 않는다.
  - 로그인 유지 토큰은 SHA-256 해시로만 저장하고 형식을 검사한다.
  - 스키마 식별자는 `sql.Identifier`를 쓴다.
- **DB 오류 로그:** `db.redact`를 거친다.
- **Streamlit:**
  - 행 위젯 key는 행 id를 쓴다.
  - `st.camera_input`은 토글을 켰을 때만 만든다.
- **저장소 관례:** 대상 파일에 KST 작성 주석과 한국어 주석이 있다. `.gitignore`는 `.env`와 `.streamlit/secrets.toml`을 제외한다.

## 확인하지 못한 부분

- 실제 OpenRouter 응답과 실제 Postgres 동작(`RUN_LIVE_DB`)은 확인하지 않았다. 9번은 실제 DB 점검이 필요하다.
- 7·8·14번은 Streamlit 실행 중 동작에 달려 있어 앱을 띄워서 확인해야 한다.
- 4·6번의 동시 접속 상황은 재현하지 않았다.
- `st.html` 스크립트가 배포 환경에서 쿠키를 실제로 심는지는 확인하지 않았다.
- 로그인 유지 쿠키는 JS로 심기 때문에 HttpOnly를 붙일 수 없다. 그래서 XSS가 생기면 토큰이 노출될 수 있다는 구조상의 한계가 있다.
